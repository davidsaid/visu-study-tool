# The web app

Plain HTML, CSS and JavaScript, with no build step. `index.html` loads classic scripts in this
order: `data/collections.js`, `app/collection.js` (which writes the script tags of the open
collection's `data/<id>/*.js`; see `docs/data-format.md`), `vendor/ts-fsrs-5.4.2.umd.js`, then the
files below. There are no ES modules and no `fetch()`, so the site works when `index.html` is
opened from a downloaded folder (`file://`) and on GitHub Pages. Nothing loads from another host
except a species' YouTube video, and only after a click (`youtube-nocookie.com`).

| File | Holds |
|------|-------|
| `collection.js` | Picks the collection (`visu-collection` in localStorage, or `?c=<id>`) and loads its data |
| `i18n.js` | `L(es, en)`, bilingual helpers, fixed labels (skills, levels, fact fields, IUCN) |
| `engine.js` | Grading, the intent router, FSRS scheduling, mastery, distractors, session building, streak, badges, export/import. No DOM, no storage |
| `store.js` | The progress object in `localStorage`, one key per collection (`visu-progress-v1` for vertebrados, `visu-progress-v1:<id>` for the others); its shape is documented at the top of the file |
| `ui.js` | Shell, event delegation (`App.on`), shared fragments, the photo widget, rings and medals, export/import buttons, citation popover, first-visit notice |
| `badge-icons.js` | `window.VISU_ICONS`: one hand-drawn SVG cartoon per class, order and single-species batch (keyed by node id, with the species drawn), plus `cambios`, a list page for the changes batch; `App.medalSVG` draws it inside the ring when given `opts.node` |
| `views-learn.js` | "Primer vistazo": a group's species (or a class's orders, or a batch: single-species orders, changes in the list) one by one, nothing graded; "¿Cuál sobra?", the odd one out; "¿Este o este?", the pair drill |
| `views-practice.js` | Today, level picker, photo → name session, "¿Qué grupo es?", exam sheet, "¿Cuál es?", Mock VISU, summaries |
| `views-explore.js` | The progressive-disclosure tree (full, or study mode rooted at the list's classes), species search, species and group cards, badges |
| `views-info.js` | "Cómo funciona" (saving progress, and the study plan: route `#como-funciona-plan` jumps to it) and settings |
| `main.js` | Boot and the hash router |
| `style.css` | The approved prototype 5 stylesheet, plus a short block of additions at the end |

Tests: open `tests/engine.html` (engine assertions; prints `RESULT: PASS` or
`RESULT: FAIL n/m`). `tests/harness.html?s=<scenario>` drives the app in an iframe for
screenshots and the persistence check; from `file://` it needs Chrome's
`--allow-file-access-from-files`. `bash tests/run-scenarios.sh <chrome> <site>` runs the scenarios
with their expected results; `<site>` is a throwaway copy with a second, test-only collection,
built by `.venv/bin/python tests/fixture_site.py <dir>`.

## How a screen is written

A view function renders its whole screen as one template string into `#main` (and `#aside`). It
does not bind events: each view file declares its handlers once, at load, with
`App.on(type, selector, fn)`, a delegated listener on `document`, so a redraw never needs
re-binding. A handler changes state, then calls `App.redraw(view, focusSelector)` to draw again
and give the focus back to the control that was used. Repeated markup lives in small helpers
(`App.cardLink`, `App.mistakeHead`, `App.draftTag`, `App.extLink`, `App.carousel`); styling lives in
`style.css`, and the only inline styles are computed values (bar widths, photo crops).

## Decisions taken while building (2026-11-01)

| Decision | Why |
|----------|-----|
| **Two states per card.** `m` is the FSRS state, updated only by answers on Hard without hints (Hard sessions, the exam sheet, Mock VISU). `p` is a light counter updated by every answer | The mastery rule: only Hard without hints counts toward "dominada" |
| Easy and Medium re-show a miss or a guess within the session (re-queued 3–5 cards later, at most twice) and schedule the card again at 10 min, 1 day, then 3 days | They must still drive practice without touching FSRS |
| A card is due at the earlier of the two due dates. After a Hard answer, FSRS alone decides | One simple rule for the Today counts |
| Visible progress per card: Easy/Medium streaks give up to 50 %; the FSRS state gives the rest; only a mastered card shows 100 % | "Easy and Medium raise visible progress" without faking mastery |
| Card mastered: FSRS retrievability ≥ 0.90 and stability ≥ 7 days. Species tiers bronze / silver / gold as in `learning-design.md` | From `software-design.md` §3.6 |
| FSRS rating on Hard: wrong → Again; guessed → Hard; unsure → Good; sure → Easy, except on a card's first review, where sure → Good | Easy on a first review gives ~8 days of stability, which would mark a card "dominada" after one answer |
| A valid other class or order typed in its box is logged as `wrong`, not `wrong_species` | It names a whole group, not one confusable species |
| **Group cards** (2026-11-02, progress `schemaVersion` 2). "¿Qué grupo es?" shows up to four species of one class or order (`E.groupItems`) and asks for its name. Each group is a card, `order:Accipitriformes:group`, with the same `{ p, m }` state and the same rules as a species box; it runs in the photo → name session (`game: 'grupo'`), graded through one member species. New groups come classes first, then larger groups first, with their own daily allowance; a scope never asks for the group that holds the whole scope. Group cards don't count toward species mastery, readiness or badges | David, 2026-11-02: the games reinforce animals already known; a beginner needs to get familiar with the list group by group first. Older copies of the tool refuse a newer backup (version 2 or later) as "newer" instead of silently dropping the group cards |
| "¿Este o este?" builds its pairs from the log: every `wrong_species` answer opens a pair; three right drill answers in a row (`game: 'par'`, the pair's other species in `with`) settle it (`E.openConfusions`). Look-alike notes from the cards fill the round. Progress `schemaVersion` 3 | David, 2026-11-02: learn the difference between similar animals, starting from the ones actually confused |
| "Primer vistazo" slides show what the names say (species etymology; for orders, the group's etymology with "-iformes", "shaped like", set apart), and every 4 slides a pause asks "which one was…?" among the last 4 (photos re-drawn), ungraded, with one more try after a miss | David, 2026-11-08: she is learning the Latin and Greek roots from the first look; naming what was just seen teaches more than looking alone (research report, Tanaka et al. 2005) |
| "Primer vistazo" and "¿Cuál sobra?" store no answers (the odd one out only counts the study day). A finished first look adds its group to `ui.looked`, so Today suggests the next order; its closing check is a one-off round (`App.onceSession`) on that group, shown even when the day's new cards are used up (`introduce`), that leaves the saved practice group and level alone | They are for getting familiar; the scheduled practice stays in the photo games. David, 2026-11-02: after a first look, practice stayed locked to that group and Today kept offering the same one |
| Once every group has had its first look, Today keeps the "Primer vistazo" card: it says so, suggests looking again at the order with the most open mistakes (the Mis fallos rule) and points to Explorar for the others | David, 2026-11-08: on her iPhone the card had silently gone (all 49 orders looked), which read as a Chrome bug |
| Today's "Primer vistazo" card opens a menu (`#vistazos`): one fixed 150 px square tile per order (only the number per row changes: 2 on most phones, 1 on 360 px ones; names break before "-formes", "-dactyla" or "-morphia") with a first look and the single-species batches: the suggestion first, then the most species not started first (ties in tree order). Each tile is a badge medal (ring: share of its species mastered; gold once its order badge is earned) with ✓ when looked at, a red count of open mistakes and the species not started. Orders come from the species, not `groupItems`, which drops a class's only order (the lampreys) | David, 2026-11-09: a way to practise any group again; then square tiles reusing the badges, no class sections, a fixed size; he chose 150 px everywhere over 3 a row on a phone (which caps a tile near 100 px), and most new species first. Orders with 2 species and the batches have no badge, so all tiles use the medal drawing and the same mastery measure |
| Badge medals show a cartoon of an iconic species of the group (62: 50 orders with a first look, 3 batches, 9 classes) on a light disc inside the progress ring; habit badges and nodes without a cartoon keep their letters. Drawn by hand as SVG in this repo (MIT), each keeping the species' real field marks; decoration only, never a study image | David, 2026-11-09: make the badges more visually interesting; no image generator is available, so they are vector drawings, approved from 14 samples |
| Species alone in their order in the list (50 of 308) get their first look in three batches ("Otros peces", "Otras aves", "Otros tetrápodos"; the tile says "órdenes con 1 sola especie en el bestiario", since the real orders have more species), `solos:peces`, `solos:aves` and `solos:tetrapodos` (`E.soloLooks`), offered after the orders; their closing check uses the batch as its pool (`opts.pool`) | David, 2026-11-08: she had looked at every order but had never seen these 50; he chose batches by big branch over one-slide looks |
| **Bestiary changes** (`changes.csv`, built into each species' `changes`). The changed species form one first-look batch, `cambios:<latest date>` (`E.changeLook`), tile pinned after the suggestion with a generic list-page icon. Today suggests it first while it is unlooked and she had started one of those species. Slides and species cards show old → new; after a miss whose answer was the old value, the feedback says it was the answer before that date. A later change gets a new key, so it is offered again | David, 2026-11-10: the 4 Nov version of the list moved the swift and the hummingbird to Apodiformes; students who memorised Caprimulgiformes need to study those species on their own |
| Restoring a copy over existing progress asks: **Combine** (default) or Replace. `E.mergeProgress` joins both logs without duplicates; a card answered on both sides is rebuilt by replaying its answers in time order through `applyAnswer` (deterministic, no fuzz), a card whose answers all come from one side keeps that side's state; days take the larger count, badges the higher tier, `ui.looked` the union; this browser's settings stay. Merging the same copy again changes nothing | David, 2026-11-13: she studies in two browsers. Checked on her real export: replaying her log rebuilds all 650 cards exactly, and a two-browser split merges back to the true history |
| With progress in this browser, restoring a copy **always** asks (also for a copy with no answers), and warns when the copy has none or fewer than here ("Reemplazar de todos modos"). Before changing anything, `Store.saveUndo` keeps the current progress under `visu-undo-v1` (per collection); if the browser refuses, nothing changes. The toast offers *Deshacer*, and Ajustes offers *Volver al progreso anterior* until it is used or replaced by the next import | David, 2026-11-13: a copy saved seconds after first opening the site (valid, 0 answers) replaced a browser's progress without warning |
| After a wrong species, the two cards' field marks are lined up by body part (`field_marks.parts`), then length, mass and activity | David, 2026-11-02: only 135 of 1,379 same-order pairs had a written look-alike note; show the differences for every pair |
| Daily session: due reviews (most overdue first) and new cards share it, with up to a third kept for new cards while the day's allowance lasts (`E.sessionSplit`); unused room goes to the other kind. New cards come first from groups whose first look was finished (`ui.looked`), then in tree order. With an exam date, Today suggests the new species a day that start every remaining one 3 days before the exam (`E.suggestNewPerDay`), applied only if she presses the button | David, 2026-11-08: with 546 of 558 cards due, her daily session was all reviews and new species never came, while the species she had looked at waited |
| Easy is a per-card on-ramp: multiple choice until the card has been answered right once, then typed with hints (Medium) from the next time, logged as level 2 (`levelFor` in `views-practice.js`) | David, 2026-11-08: recall practice beats recognition for what the exam makes her write (research report). It does not change review gaps: Easy and Medium both stop at 3 days; only Hard uses FSRS |
| After a miss, "Inténtalo otra vez" (the primary button) asks the same question once more from memory: a fresh photo, reshuffled options, no hints; it is not recorded (the miss is, and the card still comes back a few cards later). Photo → name, "¿Qué grupo es?" and "¿Cuál es?"; not the exam sheet or the mock. A misspelling shows the correct form large with the letters she missed marked (`markedCorrect`), hers small | David, 2026-11-08: retry failed questions once after seeing the answer. Seeing a misspelling weakens spelling and producing it strengthens it (research report) |
| "Mis fallos" (`#fallos`, `E.buildMistakes`): species cards missed in the last 7 days and not right on two different days since, newest misses first, in a normal photo session that records and schedules as usual; Today offers it only when there are some | David, 2026-11-08; successive relearning (research report) |
| Confidence is the check: a pick (photo, option) can change freely, and tapping "Lo adivino / Dudo / Lo sé seguro" submits it. Typed answers and the exam sheet are fixed by "Comprobar" / "Entregar hoja" first. On screens under 1000px the confidence buttons and a right answer sit in a bar fixed at the bottom (`.answer-bar`; the tab bar is hidden while practising) | David, 2026-11-08: on a phone she had to scroll to answer, then again to see the result. Supersedes "a separate Comprobar after the confidence" (2026-11-01); a tap on a photo is still never an answer |
| "¿Cuál es?" is logged but schedules nothing | It is a recognition scaffold (`software-design.md` §3.2) |
| Medium distractors that run short fall back to the closest species available, like Hard | The brief only defined the fallback for Hard |
| Mock VISU: marked out of 10; 5 or more passes ("Simulacro superado") | The Spanish pass mark |
| Badges: class badges at 80 / 90 / 100 % of species mastered; "Dominio de" ("Mastery of") for orders with ≥ 3 species at 100 %; "Primera página" (first finished session); "Racha de 7 días" (one missed day a week forgiven). Earned badges are stored and never removed | v1 scope from the brief |
| Readiness: mean FSRS retrievability over every exam card of all species, forecast at the exam date or 7 days ahead; unseen cards count 0. A daily snapshot feeds the trend line | `learning-design.md`, "Exam readiness" |
| **Collections.** One site, one collection open at a time; switching (Ajustes) remembers the choice and reloads with the other collection's data. Each collection keeps its own progress and copies; a copy is refused by another collection, with its name | David, 2026-11-01: invertebrate and arthropod exams will follow. Reloading keeps every view free of "which collection" logic |
| The vertebrate collection keeps the old storage key | Existing progress needs no migration |
| Videos are credited to their channel (title, channel link, date checked); no video comes from the bestiary document as such | David, 2026-11-01: GitHub holds only our code and compiled information |
| A card opened from a practice screen ("Abrir ficha", the species names in a comparison) shows "Volver a la práctica"; going back, by that button or the browser's back, resumes the same question. On a phone the card scrolls into view | David, 2026-11-01: see the animal's details from the mistake screen without losing the session |
| Every card ends with a "report an error" link: a prefilled GitHub issue (card id and collection, nothing else) | David, 2026-11-01: students review the draft texts as they study |
| Every question draws its photo at random (repeats allowed): photo → name at every level, the exam sheet, the mock and the "¿Cuál es?" tiles. The draw is kept while that question is on screen | David, 2026-11-01: learn the animal's features, not a picture's composition or its place in a session |
| Every large animal photo is one widget, `App.carousel` in `ui.js`: all the animal's photos (arrows, counter, swipe, arrow keys), starting on a random one, with its credit kept in step (or held back until the answer). Used on the species card, every level, the exam sheet, the mock, the "¿Cuál es?" options and the side-by-side comparison. Tapping the photo (or its ⤢ button, the only way in "¿Cuál es?", where a tap picks) opens the same widget large in a `<dialog>`; it keeps the source's alt text and credit rule and moves the source along. It flips itself in place, so typed answers, picks and focus stay; a screen that needs the photo on show registers `App.carouselStep[key]`. Small thumbnails that link to a card stay `App.tile` | David, 2026-11-01: some photos are hard to identify; define the photo widget once and reuse it. (Until then Medium, Hard and the sheet showed one photo, as the exam does) |
| Only species with photos appear in the games; Today says how many have none | A photo question without a photo is impossible |
| A missing photo file shows the "no photo yet" placeholder | Media can be regenerated independently of `data/<collection>/media.js` |
| Default theme auto (follows the system's light or dark setting); light and dark can be chosen in Ajustes | David, 2026-11-01. The prototype was signed off in light |
| `?nostorage=1` simulates a browser that blocks storage | To test the warning banner |

Progress read from localStorage or an imported file goes through the whitelist validator
`normalizeProgress` (see `docs/data-format.md`, "Learner progress"), and every value rendered
into HTML goes through `I.esc`; links from data go through `I.url` (http/https only).

Not done in v1: confusion-log driven duels, merge on import (import replaces, after
validation), raising retention near the exam date, photo pins.
